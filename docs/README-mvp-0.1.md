# ИД ИТС — пилотный интерфейс НВК (0.1)

Локальный рабочий прототип для согласования процесса ПТО/прораб. Пока не предназначен для реального учёта, подписания или передачи исполнительной документации заказчику.

## Уже работает

- Обзор пилотного объекта «Озон Крым», НВК.
- Перечень элементов, добавление объектов работ через ПТО.
- Чек-лист операций: монтаж, исполнительная съёмка, испытание/проверка.
- Отметка прораба с датой, ФИО и примечанием; отметка и её отмена остаются в журнале событий.
- Защита от повторной отправки одного события по `client_request_id`.
- История редакций проекта с перечнем изменений.
- Снимок состояния перечня в новой версии схемы.
- Локальное постоянное хранение SQLite в Docker volume.
- Контейнер собирается через Docker Compose; порт приложения привязан к `127.0.0.1`.

## Демонстрационные данные

Колодцы К-01, К-02 и участок ТР-01 — заглушки интерфейса, а не объекты, считанные из проекта Озон Крым. До загрузки проектного DXF и сметы их нужно заменить реальным перечнем. Поля размеров, координат и высот не подставляются из отметки прораба.

## Запуск локально

```bash
cd id-nvk-starter/mvp
python -m pip install -r requirements.txt
APP_DB_PATH=./data/id_nvk.sqlite3 uvicorn app:app --reload
```

Откройте `http://127.0.0.1:8000`. API документация: `/docs`; состояние: `/api/health`.

## Запуск в Docker

```bash
cd id-nvk-starter/mvp
docker compose up --build -d
```

Интерфейс локально доступен на `http://127.0.0.1:8000`. Данные переживают пересоздание контейнера в volume `id_nvk_data`.

## Ограничения и следующий этап

- Сейчас используется SQLite; перед эксплуатацией заменить на PostgreSQL, настроить регулярные резервные копии и проверку восстановления.
- Нет учётных записей, разграничения ролей, аудита входа и управления доступами. Не публиковать в интернет и не заносить реальные рабочие данные до внедрения аутентификации и HTTPS.
- Нет импорта DXF/сметы, сопоставления элементов с проектными объектами, редактора схем, расчёта фактической геометрии и создания DXF из проверенной геодезии. В родительском каталоге есть отдельный технический прототип DXF, но он ещё не подключён к интерфейсу.
- Нет генерации АОСР, журналов, печатных форм и электронной подписи.
- Нет интеграции ИИ; на следующих этапах подключается серверный маршрутизатор провайдеров. ИИ не утверждает документы и не придумывает замеры.
- Общий макет ролей сейчас демонстрационный. Следом нужно добавить пользователей и роли ПТО/прораб/руководитель, а затем импорт DXF, сметы и проектные редакции.

## API

- `GET /api/overview` — счётчики объекта.
- `GET /api/elements` / `POST /api/elements` — перечень объектов.
- `POST /api/events` — событие выполнения/отмены.
- `GET /api/history` / `POST /api/revisions` — история проектных редакций.
- `POST /api/schema-versions` — снимок текущего перечня и отметок.
- `GET /api/documents` — демонстрационные статусы документов.

Это первый проверяемый интерфейс процесса, а не финальная архитектура хранения и безопасности. Следующий практический вход для заполнения реальными элементами — исходный DXF НВК и соответствующая смета/ведомость.
